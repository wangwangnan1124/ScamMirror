# Security Policy

## Supported version

Security fixes are currently provided for the latest `0.1.x` release.

## Reporting a vulnerability

Please use GitHub's **Report a vulnerability** flow when private vulnerability reporting is enabled for the repository.

Do not include personal data, real victim conversations, active phishing URLs, credentials, API keys, verification codes, or financial account information in a public issue.

For ordinary non-sensitive bugs, open a GitHub issue using the bug report template and include only synthetic reproduction data.

## Security boundaries

ScamMirror is an educational risk-assistance tool. A report is especially useful if it shows that the product:

- exposes or persists user input;
- opens or follows untrusted content without consent;
- labels a critical-risk example as low risk;
- displays evidence that does not exist in the input;
- lets instruction-like scam text override safety behavior;
- suggests contacting a number or URL supplied by the suspicious message.

We aim to acknowledge a private report within seven days. Do not test against real victims, accounts, institutions, or active scam infrastructure.
